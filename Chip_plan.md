## Principle
- Новый дизайн 08.10 — **эталон стиля**, старый контент подтягиваем к нему, а не наоборот
- GitHub Pages = push из master: каждый коммит publikуется → коммитим только проверенные этапы
- Бэкап перед любой правкой; удаление — только в `~/.trash/` или через git (история хранит)

## Этапы

### Этап 0. Инвентаризация (read-only, без изменений)
1. Точный учёт всех HTML: путь, размер, дата, наличие входящих ссылок, «сиротство»
2. Сравнить `runes/` (35) vs новый `runes.html` — дубль или детальные страницы?
3. Оценить качество старого контента (family/, world/, events/): тексты, обрывки, диакритика/encode
4. На выходе: `memory/CONTENT-INVENTORY.md` + уточнённый список «восстановить / объединить / в архив»

### Этап 1. Решения Шефа (блокирующие)
- **Р1:** судьба old-content: (а) вернуть в навигацию как каталоги, (б) склеить короткие страницы в тематические сборники, (в) часть в архив
- **Р2:** рестайлинг старых страниц под новый CSS — оборачиваем все ~220 стр., или делаем новые страницы-каталоги с выборками?
- **Р3:** `scandic-v2`/`scandic-host` — продолжать, или считать закрытыми?

### Этап 2. Каркас навигации (после решений)
1. Каталогные секции: «Население миров» (боги/великаны/чудовища → family/), «Девять миров» → world/, «События» → events/, «Руны» → runes/ (если не дубль)
2. Хлебные крошки + единый nav/footer на подтянутых страницах (скрипт-обёртка, бэкап каждой группы)
3. Перелинковка: из карточки персонажа — ссылки наrelated (семья, мир, события)

### Этап 3. SEO и карты сайта
1. `scripts/generate_sitemap.py` — перегенерить sitemap.xml под реальный набор URL (+ lastmod из git)
2. Унификация title/description восстановленных страниц («{Название} — Scandic | Скандинавская мифология»)
3. robots.txt/OG-теги — проверить

### Этап 4. Уборка
1. `.bak-20261008-*` из корня → `~/.trash/20261020/` (или git rm — они в истории)
2. Мусорные/пустые файлы, сиротские картинки → список на утверждение, потом чистка
3. Проверить вес репо, при раздутии — обсудить git GC / LFS (НЕ делать без решения)

### Этап 5. Верификация и публикация
1. Линк-чек всего сайта (все HTML, href+src) — 0 битых
2. Выборочный рендер 5–10 страниц (скриншоты) — вёрстка не поехала
3. Ком этапaми в `master`, push; проверка GitHub Pages после пуша (200 + свежий контент)
4. Отчёт Шефу + апдейт PROJECT_LOG.md

## Риски
- Прямая публикация push'ем → работаем в отдельной ветке `restore-content`, merge после верификации (решение Р4: ветка или master?)
- Диакритика (ǫ, ǫ́, þ, œ) в именах файлов — уже ломала ссылки в августе; все новые href — через транслит-маппинг из августовского `fix_img_refs.py`
- Объём большой (~220 стр.) → этапы независимы, каждый с откатом через git
